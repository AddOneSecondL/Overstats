# 补丁阅读器

默认 `view=auto`：大小补丁均生成一张精简改动图。`view=overview` 显式选择速读图，`view=detail` 保留含开发者评价的完整正文分页。

速读图去掉开发者评价，不再限制英雄数和每位英雄条数；威能标题保留为上下文，5v5/6v6 条件不丢弃，系统正文和地图图片也保留。按内容自动增长图高，超大更新仍是一张长图（用户明确选择）；超过 6000 万像素时拒绝生成，避免无界内存分配。原文链接随回复包提供。

每条改动单独着色：绿色增强、红色削弱、黄色调整。识别标量、同向区间、每秒数值与明确百分比增减，保留条件和单位。冷却降低、角色身体判定体积缩小、冷却缩短幅度增加等按属性方向判断；持续时间只对已知技能上下文判断。新机制、自伤、混合方向区间和无法确定的语句仍为调整，不给混合英雄贴整体强弱标签。颜色是规则判断，不是官方评级；不新增模型总结或翻译调用。

普通模式、角斗领域分别分框。生命值、护甲、护盾分别用白色、黄色、蓝色倒角方块；伤害、CD、治疗、速度用本地绘制图标，保留必要限定词。下载并显示原文技能图标；原文未配图或资源不可用时用通用符号并保留技能名。属性图标不依赖网络或字体特殊字符。

## 接口

- `POST /api/v2/patch-notes`：结构化 JSON。
- `POST /api/v2/patch-notes/image`：当前页 PNG。
- `POST /api/v2/patch-notes/replies`：JSON、导航元数据及文字/图片回复包；控制面板使用此接口。

可选参数：`patch_kind`（沿用原值）、`view`（`auto` / `overview` / `detail`）、`section`（目录 ID 如 `s5` 或标题）、`hero`（英雄名）、`page`（从 1 开始）、`patch_id`（响应返回的补丁快照标识）。

翻页和章节跳转应直接使用 `reader.next_request`、`previous_request`、`detail_request`、`overview_request` 或 `reader.sections[].request`。这些请求携带 `patch_id`，避免官网更新后翻到另一版补丁。未知筛选返回 404，无效页码返回 400。

## 内容与缓存

按原始文档顺序保留章节、英雄、技能、段落、列表、开发者说明和地图图片。不能匹配到结构化正文的源文本会进入“其他原文（解析补充）”，并在 `extraction` 记录补充行数。该检查只保证文本覆盖，不代表自动判断原文语义是否正确。

固定栏目名称本地中文化；翻译调用流程不变。解析缓存版本更新，避免继续复用旧解析结果。图片按补丁快照、筛选、页码和渲染版本缓存，只下载当前页所需图片，同一请求合并处理。缺失图片不写入永久图片缓存。

## 验证

在仓库根目录运行 `python -m unittest validation.patch_reader_checks`。覆盖原文顺序与漏项、分页、筛选、快照、并发缓存、参数校验和服务入口。控制面板可直接使用总览、完整正文、前后翻页和章节跳转。

历史页面离线复验：`python -m validation.patch_history_checks sources.json output_directory`。清单每项包含 `source`、`url`、`file`。检查原文文本覆盖、英雄非评价条目覆盖及每个补丁实际出图，输出报告和 PNG。此验证不调用翻译，也不证明未来官方页面结构或语义永远不变。
