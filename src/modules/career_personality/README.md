# 生涯人格测试（未完成，暂时隐藏）

**状态：未完成。** HTTP 查询页和自动路由入口已暂时隐藏；现有代码、英雄标签、样例及内部调试接口保留，仅供继续开发与验证，暂不作为正式功能开放。

使用小程序的完整英雄生涯列表，按正时长和可解释的英雄软标签生成游戏偏好画像。标签覆盖当前本地配置的 54 位英雄，并保留官方职责、子职责、风格权重、技能依据和规则版本。只描述游戏偏好，不推断现实性格或实际团队配合。

## 开发验证调用

`POST /api/v2/career-personality` 返回 JSON；`POST /api/v2/career-personality/image` 返回 PNG。

```json
{"player":"Player#12345","mode":"quick","xcxtoken":"<XCXTOKEN>"}
```

`player` 支持完整战网名称或九位数字 ID。HTTP 兼容 `player1`、`bnetID`、`bnet_id`、`bnetId`、`battle_tag`、`bnet_name`、`target`；票据兼容 `xcxToken`。名称解析复用战网搜索，直接传数字 ID 不依赖名称搜索。

`mode` 支持 `quick`、`competitive`、`stadium_quick`、`stadium_competitive`，默认快速。各模式独立计算，只支持全生涯累计；`season` 只允许省略、空值或 `total`，不回退赛季或队列。

HTTP 查询页和自动路由暂不展示或提供“生涯人格测试”。开发验证可直接调用保留的 HTTP 接口，并将 `xcxtoken` 放在请求体中。

## 数据与计算

- 数据层复用 `CareerCompareModule.fetch_player()`，在生涯对比筛选前三英雄之前读取完整列表。验证返回玩家身份；详情只从同模式、明确累计范围补齐。竞技的单赛季与快速详情不会混入竞技累计。
- 正时长来自上游取整小时。零小时条目不参与面积或分母，并明确零小时也可能包含少量实际游玩。缺失、负值、非法单位、重复条目会降级画像，不制造时长。原始列表含非对象条目时拒绝响应，避免静默遗漏记录后误报完整画像。
- 枪型仅在输出英雄中计算；长枪、短枪、其他为作战风格标签，不强制等同严格弹道分类。混合武器可以软分配，飞行物、光束、近战单列其他。
- 放狗／地推／消耗权重每英雄合计为 1。玩家构成为各英雄时长乘对应权重，再除以已标注时长。所有维度返回完整分母、已覆盖时长、覆盖率和逐英雄贡献；未知英雄仍保留在总时长中。
- 机动、侧翼、自主作战工具、协同工具各为独立的 0–100 倾向分。自主和协同不是互斥端点，也不是玩家真实走位、合作或实力评分。
- 职责分布优先使用生涯接口的职责。若与当前配置不同，保留统计口径并在 `role_mismatch` 与 `notes` 注明。当前标签不能还原历史版本的技能与职责变化；角斗强化组合也可能改变实际打法。
- 主称号由透明阈值规则决定，少于 10 小时不生成稳定称号，核心标签缺失或记录异常时保留待补全状态。规则版本及触发条件位于 `persona`。
- 每10分钟伤害、消灭、助攻、治疗只有在明细数值与对应六维个人值吻合时才使用六维 `median` 比较。不给阵亡、单独消灭、最后一击制造参考；存活、协防不擅自映射。缺失和零参考不计算相对差异。
- 辅助标签要求该英雄至少 5 小时，相应两个指标均比中位数高至少 10%。火力活跃使用伤害＋消灭，支援活跃仅用于支援职责的治疗＋助攻，避免把坦克自疗当团队支援。阈值是启发式产品规则，参考人群段位和覆盖范围未披露，不视为精确百分位或实力分档。

## 维护与验证

修改 `hero_tags.json` 即可更新风格标签；保持 `version`、`definitions`、`rationale`、技能 `evidence` 和来源。`tags.load_catalog()` 校验字段与权重，并按文件变动刷新缓存。`catalog_coverage()` 对照本地英雄配置检查漏标的新英雄。权重是编辑规则，尚未用对局样本校准。

离线验证：

```text
python -m unittest discover -s validation -p "career_personality_*_checks.py"
```

服务不保存票据或玩家响应；票据字段不进入 dataclass repr，错误不回显上游响应、请求头或票据。正式 API 无本机凭据文件依赖。真实样例运行脚本位于工作区 `previews/career-personality-real`，仅作为本地验证工具。
