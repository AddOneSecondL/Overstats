# 对局奖项与时间线

今日、昨日、本周总结使用最佳表现 / 最大突破双栏。展示 S/A/B/C/D，内部数值仅用于排序。评级界限：S ≥65，A ≥57，B ≥45，C ≥35，其余 D；数据不足显示“—”。这是可见统计的启发式评级，不是官方竞技评价。

## 参照来源

最佳表现依次尝试本场同职责玩家、queryCountInfo 的个人英雄赛季数据、本次其他至少两场同英雄同模式单英雄记录。已移除固定参考线。赛季数据和本场数据都不可用时不编造评分。

最大突破优先比较时段开始前的至少五场同英雄同模式历史记录；不足时用英雄赛季数据，再尝试本次此前至少三场记录。右栏标题区分“相较赛季”“本次进步”和“当场亮点”。赛季统计可能包含本次对局，因此不声称是独立的过去历史样本。

评分完全不要求本地数据库。queryCountInfo 按 sport / leisure 和赛季分别请求，五分钟内存缓存，最多128项，每项12秒超时。历史与赛季请求并行。任一可选数据源失败不阻断本次总结。

## 赛季口径

解析 presetsHeroUseSummaryList / openHeroUseSummaryList / v6HeroUseSummaryList，按对局队列选择，模糊队列且存在多个分组时不混用。英雄至少五场。statPerTenMinCount 优先；只有 statAveCount 时与本场总数比较，绝不把场均假装成每十分钟。缺失字段不计零。混合英雄整场数据不与单英雄赛季均值比较。

本场参照使用平滑经验百分位，死亡反向，按职责权重汇总，胜负占5%。赛季比较按相对均值的变化转换为内部排序分数。至少三项可比核心指标，包含死亡，覆盖至少60%职责权重。短于三分钟、乱斗、模式未知不参评。

## 特色数据

使用配置的 heroAttrList 中 valueType=特色数据 的指标，与英雄 statMap 和同英雄赛季统计按 valueGuid 关联。英雄至少使用三分钟；计数换算每十分钟，比例原样比较；仅单英雄对局可用特色场均参照。零基准不计算增长率。

展示最多两条特色提升并保留核心指标；比例变化显示“百分点”，计数变化显示“百分比”。有特色提升时，赛季排序允许20%特色权重，防止单项压过整体表现。未知语义、缺失基准的指标不生成提升结论。

## 视觉

地图背景、主英雄头像、其他英雄缩略图；竞技使用 comp.png，职责使用 tank/dps/healer 素材。竞技段位来自该局玩家或 match.rankInfo，显示对应段位图标与小段；无快照显示“段位未知”，不拿当前赛季段位冒充历史段位。边框颜色对应字母评级，胜负单独呈现。素材失败保留文字布局。
