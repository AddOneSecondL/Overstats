# 英雄对比

POST `/api/v2/dashen-hero-compare` 返回JSON；追加 `/image` 返回PNG。

```json
{"player1":"PlayerA#12345","player2":"PlayerB#67890","hero":"安娜","mode":"quick"}
```

hero可省略：默认两名玩家各自选取可用赛季时长前三，按使用排名并列展示，不是全生涯累计，也不强行让不同英雄的特色数据排名。指定hero时只取该英雄，支持配置名称、GUID和项目英雄别名。模式沿用云图，默认快速；season可指定起始赛季。

每名玩家独立查询起始赛季，然后严格按S-1、S-2、S-3依次回退；找到有使用时长的数据即停止。指定英雄时其他英雄的存在不阻止回退；不足三名不拼接多个赛季。上游失败不当作无数据；最终无数据仍保留空位，显示对方结果。图片与JSON标注实际来源赛季和查找范围，缺失指标不补零。

机器人：`英雄对比 玩家A#12345 玩家B#67890 [英雄] [快速|竞技|开放|开放竞技]`，支持LLM工具hero_compare。


## 完整指标与数据库参照

图片按指标逐行展示基础数据及配置中的全部特色数据，不截取条数；无值显示破折号。画布随行数增长，长名称换行。同英雄使用指标GUID对齐，且仅同单位、方向明确、双方都有值时以绿色高亮较优一侧；阵亡等反向指标明确标注越低越好。异英雄、平手、缺失及未知方向不评优。

数据库统计遵循is_database_write_enabled开关，关闭时不访问数据库。开启时显示同英雄库内玩家均值和Top%，每人先求均值，再按玩家等权汇总。库表没有在此接口按赛季和模式筛选，因此页脚明确标注全量样本口径。计数仅用每10分钟数据参与数据库排名，场均不冒充每10分钟；百分比原始小数统一转换。KDA采用一致比值口径。场数、时长及无同口径参照项不强行给排名。至少5人显示Top%，方向未知仅显示均值；无记录或查询失败保留个人数据。
