# 英雄图文百科与定向查询

保留原接口及 `hero?问题` 格式：

```http
POST /api/v2/ow_hero_wiki
Content-Type: application/json

{"hero":"猎空","question":"闪现最多可以储存几次？冷却多久？"}
```

同一请求发送到 `/api/v2/ow_hero_wiki/image` 可获取 PNG。问题留空为完整百科；填写问题后图片展示回答、命中的技能或威能及来源。调试页面选择「英雄百科」，填写英雄与问题，选择图片模式即可。

## 数据与检索

- 数据来自既有 Fandom Wiki 抓取与解析流程，中文名称和简介沿用本地 query_tool 配置。
- 威能不再按列表位置套用中文名：仅采用显式名称匹配，否则使用 Wiki 名称及说明（配置模型后尝试翻译）。合作模式的备注明确标注 PvE，避免其数值混入普通模式。
- 对概览、基础属性、技能参数、威能、所有机制备注及 6v6 备注分块，使用中文双字切分、英文词切分、术语扩展和 BM25 检索。明确指定技能时限定该技能，优先返回参数正文。
- 取前 5 个片段交给现有分析模型，要求以 `[1]` 格式引用。无需额外数据库、embedding API 或相邻 `overstats-wiki-rag` 目录；这是单英雄结构化资料范围的检索，并非全站 Wiki 搜索或向量检索。
- JSON 新增 `citations`（编号、标题、正文、来源 URL、内容哈希、所属条目、检索分数）及 `answer_mode`。
- `generated` 表示生成回答且引用编号通过检查；`extractive` 表示仅返回检索原文（未配置模型、调用失败或引用无效）；`insufficient_evidence` 表示没有命中资料。编号校验不等价于事实正确性验证。
- 页面、结构化资料及答案沿用现有缓存；过期答案不再续期复用，检索上下文变化会使答案缓存失效。资料未覆盖的版本历史、故事章节及跨英雄问题仍需要扩充数据范围。

## 渲染

沿用今日总结的深色卡片、地图背景和分组强调色。加入 Wiki 英雄大图与已有本地技能图标，明确分开参数、机制说明、6v6 改动和引用。本地图标从 `ow_guess_assets/shared/hero_icons/<英雄>/Abilities|Perks/<中文名称>.png` 读取，文件缺失时保留文字卡片。修复段落换行、长 URL 换行、数值截断及问答面板高度不足。

模型配置复用项目现有 `ANALYSIS_*` 配置；没有模型仍可完成检索，但英文原文不会自动翻译。Wiki 数据可能滞后于游戏版本，页面与本地中文配置也可能不完全同步。
